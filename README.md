# NetPulse

轻量的 Windows 网速悬浮窗、流量统计和网络工具箱。所有功能免费，不收集数据，没有广告。

## 下载与安装

每个版本有两个 exe，任选一个：

| 文件 | 大小 | 说明 |
|---|---|---|
| `NetPulse-<版本>-win-x64.exe` | 约 1 MB | 需要先安装 [.NET 10 桌面运行时](https://dotnet.microsoft.com/download/dotnet/10.0)（缺少时 Windows 会提示下载） |
| `NetPulse-<版本>-win-x64-full.exe` | 约 50 MB | 自带运行时，不需要另外安装任何东西 |

- **免安装**：直接双击运行。数据保存在 `%LOCALAPPDATA%\NetPulse\`，与 exe 放在哪里无关。
- **安装**（可选）：在“设置 → 安装与更新”中点击“安装到这台电脑”。NetPulse 会被复制到 `%LOCALAPPDATA%\Programs\NetPulse`，添加开始菜单快捷方式，并在 Windows 设置的“已安装的应用”中登记。不需要管理员权限，设置和统计保持不变。
  - 以后运行新版本的 exe，同一个位置会显示“更新已安装的版本”。
  - 卸载：在“已安装的应用”中卸载，或在设置页点击“卸载…”。卸载时可以选择是否同时删除设置和统计（默认保留）。如果开启了“以管理员身份启动”，它的计划任务和 Program Files 中的副本也会一并删除。
- 没有 MSIX 安装包：MSIX 必须用受信任的证书签名才能安装。
- 每个版本都附带 `SHA256SUMS.txt`，可以用 `Get-FileHash` 核对下载的文件。
- **SmartScreen**：exe 没有代码签名，第一次运行时 Windows 可能提示“Windows 已保护你的电脑”。核对校验值后，可以点击“更多信息 → 仍要运行”。

## 功能（v0.9）

### 网速与流量

- **悬浮窗**：实时显示下载和上传速度。
  - 可置顶，可拖动，拖到屏幕边缘会自动吸附。
  - 不抢焦点，也不出现在 Alt+Tab 中。
  - 可锁定位置，也可开启鼠标穿透。
  - 运行全屏游戏、视频或演示时自动隐藏。
  - 有深色和浅色两种主题，默认跟随任务栏。
  - 显示方式可选（v0.4 新增）：两行（下载、上传）、一行，或只显示合计。
  - 可选显示最近 1 分钟的迷你速度曲线（v0.4 新增）。
  - 位置按所在显示器记忆（v0.4 新增）：保存的是到最近屏幕角落的距离，更换分辨率、缩放比例或拔掉显示器后仍会回到合适的位置。
- **托盘图标**：鼠标悬停显示实时速度。单击打开流量统计，右键菜单可直接进入各个页面。
  - 可选把当前下载或上传速度直接画在图标上（v0.4 新增）：最多三个字符，图标底部的横条随单位变长（K 约三分之一，M 约三分之二，G 满格）。
- **流量统计**：显示今天和本周期的用量、30 天柱状图和每日明细，可导出 CSV。
  - 可按网络查看（v0.4 新增）：Wi-Fi 按名称（SSID）统计，其他网卡按网卡名称统计。手机热点等按流量计费的网络可以单独设置套餐，用量达到阈值时单独提醒。
  - 按网络的统计从 v0.4 开始记录，之前的用量只计入“全部网络”。
  - 范围可选最近 7 天、30 天或 12 个月（v0.5 新增）。按月视图按自然月汇总，统计默认保留 400 天，12 个月视图的最早月份可能不完整。
- **提醒**（v0.5 新增，默认关闭，都在设置页的“提醒”中）：
  - 速度持续偏高：上传或下载速度连续超过设定值一段时间后提醒一次，用于发现后台上传；速度降下来之后才会再次提醒。
  - 程序流量：某个程序当天的流量超过设定值时提醒，每个程序每天一次。需要以管理员身份运行（因为数据来自进程流量记录）。
  - 每周摘要：每周一用通知显示上周（周一到周日）的流量和相比前一周的变化，默认开启，可关闭。
- **备份与恢复**（v0.5 新增）：设置页可以把设置和全部统计（总流量、按网络、按程序）保存为一个 JSON 文件，也可以从备份恢复。恢复会替换当前的全部内容并重启 NetPulse。备份只保存在你选择的位置，不会上传。
- **实时速度**（v0.3 新增）：最近 60 秒或 10 分钟的速度曲线，显示当前、峰值和平均速度，鼠标悬停可查看任意时刻的数值。
- **流量套餐提醒**：
  - 可设置每周期流量和每月重置日。
  - 用量达到阈值或超额时各提醒一次。
  - 可选择上传流量是否计入。
- **网卡选择**：可以只看某一块网卡。自动模式默认排除虚拟网卡（VPN、Hyper-V 等），避免重复计算。
- **开机启动**，三种选项：
  - 不启动。
  - 启动：写入当前用户的 `Run` 项，不需要管理员权限。
  - 以管理员身份启动（v0.3 新增）：
    - 通过“任务计划程序”在登录时以管理员身份启动，不弹出权限提示，可以自动记录进程流量。
    - 开启和关闭时各需要确认一次 Windows 的权限提示。
    - NetPulse 会被复制到 `C:\Program Files\NetPulse`，计划任务只运行这份副本，以免这个以管理员身份运行的程序被普通程序替换。
    - 更新版本后，设置页会提供“用当前版本更新已安装的副本”。
- **界面**（v0.3 新增）：
  - 语言可选中文或英文。新安装默认跟随 Windows 显示语言，从旧版本升级的用户保持中文。
  - 主窗口可选深色、浅色或跟随 Windows 应用模式。
  - 两项都在重启 NetPulse 后生效。
- **已修复**（v0.4）：
  - NetPulse 以管理员身份运行时，再次打开 NetPulse 现在会显示主窗口。（从 v0.3 升级后，需要先重启一次正在运行的旧版本才会生效。）
  - 深色模式下，下拉框和数字框改为深色。

### 进程流量（v0.2 新增）

- 实时显示每个程序的下载和上传速度，以及开始记录以来的累计流量。
- **历史记录**（v0.3 新增）：以管理员身份运行时自动记录，按天保存每个程序的流量。可以查看今天、本周期和最近 30 天的排行，并导出 CSV。
- 可以按程序合并，也可以逐个进程显示。
- 数据来源是 Windows 内核网络事件（ETW 提供程序 `Microsoft-Windows-Kernel-Network`），统计 TCP 和 UDP 的收发字节数。
- 这项功能**需要以管理员身份运行**。未提权时，页面上有“以管理员身份重启”按钮。重启后会弹出 Windows 的权限确认，旧的实例退出，新的实例接管。
- **禁止联网**（v0.8 新增）：在实时列表中右键某个程序，选择“禁止此程序联网…”；或者点击“禁止联网的程序…”，从文件中选择程序，也可以在这里重新允许联网。
  - 通过 Windows 防火墙实现：每个程序一条出站、一条入站阻止规则，都放在防火墙的“NetPulse”规则组中。NetPulse 只读取和删除这个组里的规则，不会改动其他软件的规则。
  - 添加或删除规则需要以管理员身份运行；查看列表不需要。
  - 不能阻止 Windows 的核心进程（如 svchost、lsass、explorer）和 NetPulse 自己。阻止 Windows 目录下的其他程序前会额外提醒。
  - 已经建立的连接可能要等程序重新连接时才会断开。如果当前网络的 Windows 防火墙被关闭，规则不会生效，对话框会提示。
  - 卸载 NetPulse 不会删除这些规则（卸载时会提示还有几条），需要先在这里允许联网，或者在“高级安全 Windows Defender 防火墙”中删除“NetPulse”组的规则。

### Wi-Fi（v0.2 新增）

- **当前连接**：SSID、信号强度（% 和 dBm）、频段和信道、协议（Wi-Fi 4/5/6/7）、安全类型、连接速率、BSSID。
- **已保存的网络**：列出全部网络及其安全类型。
  - 密码只有点击“显示密码”后才会向 Windows 读取，**不会写入磁盘**。
  - 切换到其他网络或离开页面后，密码会自动隐藏。
- **二维码**：用手机扫描即可连接，界面上会提示“任何扫描者都能连接”。
- 直接调用 Windows Native Wifi API（`wlanapi.dll`），不解析 `netsh` 的输出（`netsh` 的输出随系统语言变化）。
- Windows 11 24H2 起，读取 Wi-Fi 连接信息需要开启“位置”权限。被拒绝时，页面会给出打开设置的链接。
- **附近的网络**（v0.6 新增）：点击“扫描”后列出附近的接入点，显示网络名称、信号（% 和 dBm）、信道、频段、协议和 BSSID，当前连接的那一个会标出。
  - **信道占用**：按频段画出每个信道的占用情况，并推荐干扰最小的信道，方便给路由器选信道。2.4 GHz 的 20 MHz 信道会互相重叠，所以相邻信道也按距离递减计入，推荐只在互不重叠的 1、6、11 中选；5 GHz 按各个 20 MHz 信道计算；6 GHz 信道很多，不给推荐。
  - 扫描结果里没有信道宽度，也分不出哪个是你自己的路由器，所以占用分只是参考：你自己的网络也会计入它所在的信道。
  - 扫描只是接收附近网络广播的信息，不连接任何网络，也不向网络发送数据。同样需要“位置”权限。

### 测速（v0.2 新增）

- 测量延迟（中位数）、抖动、下载和上传速度。下载和上传各用 4 路并行连接，各测约 10 秒，前 2 秒的爬坡阶段不计入。
- 服务器是 Cloudflare 的公共测速端点 `speed.cloudflare.com`，与网页版 speed.cloudflare.com 相同。
- 不发送 Cookie 或任何标识。
- 历史记录只保存在本机，最多 200 次（v0.6 起；之前是 50 次），并画成下载和上传的变化曲线，鼠标悬停可看每次的数值。
- **自动测速**（v0.6 新增，默认关闭）：可以每隔 1 到 168 小时自动测一次。开启时会提示每次会消耗几十到几百 MB 流量并立即开始第一次；全屏应用运行时会推迟；和手动测速不会同时进行。失败时也按间隔计时，不会连续重试。

### 网络工具（v0.2 新增）

- **Ping**：可设置次数，显示每次结果，并统计丢包率和最短、最长、平均延迟。
- **路由追踪**：用 Ping 加递增 TTL 实现，不调用外部命令。可选解析各节点的主机名。
- **DNS 查询**：域名正向解析（A/AAAA 记录），IP 反向解析，并显示系统当前使用的 DNS 服务器。
- **本机网络**：列出各网卡的地址、网关、DNS、MAC 和 DHCP 状态。查询公网 IP 需要手动点击（连接 Cloudflare `1.1.1.1/cdn-cgi/trace`）。
- **端口检测**（v0.6 新增）：检测某个主机的 TCP 端口能否连接，端口可以写成 `80, 443, 8000-8010`（最多 1000 个）。结果分为开放、关闭（对方明确拒绝）、无响应（通常是防火墙丢弃了数据包）和出错。Windows 在连接被拒绝后会自动重试，所以“关闭”的结果最多要等约 2 秒。只连接你输入的主机和端口。
- **局域网设备**（v0.6 新增）：列出同一网络里的设备，显示 IP、MAC、名称，并标出网关和本机。
  - 数据来自本机的 ARP 表。勾选“主动探测”后，会先向本网段的每个地址各发送一次 Ping，让不常说话的设备也出现在表里；网段大于 /24 时只扫描本机所在的 /24。
  - 名称通过反向 DNS 查询，只有路由器支持时才会有；没有内置设备厂商库。
  - 全程只在本地网络内进行，不访问互联网，需要手动点击“扫描”。

### 连接质量（v0.10 新增，默认关闭）

回答“网络稳不稳，出问题时是谁的问题”。在“连接质量”页点击开启，或在“设置 → 连接质量”中开启。

- **探测**：默认每 5 秒 Ping 一次当前的默认网关（路由器），超时 1 秒，只在局域网内进行。可以再开启外网探测，同时 Ping 一个外网地址（默认 `1.1.1.1`，可以修改），每天约 1 MB。还可以开启 DNS 检查：每次直接向当前网络的 DNS 服务器查询一次 `cloudflare.com`（不经过 Windows 的 DNS 缓存），用来发现“能 Ping 通但网页打不开”。不需要管理员权限。
- **Wi-Fi 信号**：连接 Wi-Fi 时，每次探测同时记录信号强度，在时间线上画成灰色虚线，用来看出“信号差的时候丢包多”。需要“位置”权限，没有权限时不记录。
- **断线判定**：连续 3 次没有回应记为一次断线，从第一次没有回应开始，到下一次全部有回应时结束。
  - 网关没有回应 → **本地问题**（Wi-Fi 信号、网线、路由器）。
  - 网关有回应、外网没有 → **外网问题**（运营商或上游）。只开启网关探测时没有这一类。
  - Ping 都有回应、DNS 服务器没有 → **DNS 问题**（网页打不开）。只在开启 DNS 检查时才有这一类。
  - 没有可用的网络（没有网关）→ **未连接**，单独统计，不算断线，也不计入可用率。
  - 睡眠、休眠期间不算断线，这段时间记为“未监测”。
- **页面**：当前延迟和状态；今天和最近 7 / 30 天的可用率、断线次数、网关和外网延迟（中位数和 P95，按区间估算）、丢包率；最近 24 小时按分钟着色的时间线和延迟曲线；每天的断线时长；断线列表，可以导出 CSV，方便向运营商反映问题。可以按网络筛选。
- **提醒**：断线超过设定时长（默认 60 秒）时，在恢复连接后用通知说明断了多久、是哪一类问题。每周摘要中也会加入上周的可用率和断线次数。
- 开启后，托盘图标的提示文字会显示当前的网关和外网延迟。

### 更新检查（v0.7 新增，默认关闭）

- 在“设置 → 安装与更新”中开启后，每天最多连接一次 `api.github.com`，读取发布页上的最新版本号。请求只带 NetPulse 自己的版本号（User-Agent），没有 Cookie 或其他标识。
- 有新版本时显示一条通知，点击通知打开 GitHub 上的下载页面。**不会自动下载或安装**，每个新版本只提醒一次。
- 也可以点击“立即检查”手动检查。
- 更新来源在构建时写入（见下文“发布”）。没有设置更新来源的版本不能检查更新，设置页上会说明。

## 隐私

- **平时不联网**：后台运行和统计流量时不发起任何网络连接，实测连接数为 0。
- **只在你主动操作时联网**，且只连接对应的目标：
  - 开始测速 → `speed.cloudflare.com`
  - 查询公网 IP → `1.1.1.1`
  - Ping、路由追踪、DNS → 你输入的目标
  - 端口检测 → 你输入的主机和端口
  - 局域网设备 → 只在本地网络内（ARP 和 Ping 本网段）
  - 自动测速（默认关闭，开启后才会）→ `speed.cloudflare.com`
  - 更新检查（默认关闭，开启后每天最多一次）→ `api.github.com`
  - 连接质量监测（默认关闭）→ 只 Ping 网关，在局域网内；另外开启外网探测后 → 你设置的地址（默认 `1.1.1.1`）；开启 DNS 检查后 → 当前网络的 DNS 服务器（查询 `cloudflare.com`）
- 不收集、不上传任何个人信息。
- 所有数据只保存在 `%LOCALAPPDATA%\NetPulse\`：
  - `settings.json`：设置
  - `usage.json`：每日流量，默认保留 400 天
  - `speedtests.json`：测速历史，最多 200 条
  - `process-usage.json`：每个程序每天的流量。只有以管理员身份运行时才会记录，保留天数与流量统计相同
  - `quality.json`：连接质量。每天的汇总保留天数与流量统计相同，断线记录保留 90 天（最多 2000 条），另有最近 24 小时的分钟记录。只有开启连接质量监测后才会记录
  - `error.log`：出错时才会生成，只记录在本地
- Wi-Fi 密码从不写入磁盘。

## 构建

需要 .NET 10 SDK。

```powershell
dotnet build NetPulse.slnx
dotnet test NetPulse.slnx
dotnet run --project src/NetPulse
```

### 发布

```powershell
.\build\publish.ps1                                            # win-x64，两个 exe 加 SHA256SUMS.txt
.\build\publish.ps1 -Runtime win-x64, win-arm64                # 同时构建 ARM64 版本
.\build\publish.ps1 -UpdateRepository owner/netpulse           # 启用更新检查，读取这个 GitHub 仓库的 Releases
.\build\publish.ps1 -CertificateThumbprint <证书指纹>           # 用 signtool 签名（需要 Windows SDK）
```

- 脚本会先运行测试，然后把文件输出到 `artifacts\<版本>\`。版本号取自 `Directory.Build.props`。
- **更新检查的来源**是 GitHub 仓库名（`owner/repo`），可以用 `-UpdateRepository` 指定，也可以写在 `Directory.Build.props` 的 `NetPulseUpdateRepository` 中。发布新版本时，GitHub Release 的标签要写成 `v0.7.0` 这种格式，草稿和预发布版本不会被当作新版本。
- **代码签名**：目前没有购买证书。如果以后购买了（或使用 Azure 的云签名服务），只需传入 `-CertificateThumbprint`，其他步骤不变。签名能减少 SmartScreen 警告，但新证书也需要积累一段时间的信誉。

### GitHub Actions（v0.8 新增）

代码推送到 GitHub 后：

- **CI**（`.github/workflows/ci.yml`）：每次推送到 `main` 和每个 Pull Request 都会在 Windows 上构建并运行全部测试。
- **发布**（`.github/workflows/release.yml`）：推送 `v0.9.0` 这样的标签时，先检查标签和 `Directory.Build.props` 中的版本号一致，再构建 x64 和 ARM64 的四个 exe 及校验文件，并创建一个**草稿** Release。构建出的程序会自动以当前仓库作为更新来源。检查草稿后点击“Publish release”才算正式发布，开启了更新检查的用户这时才会收到提醒。

```powershell
git tag v0.9.0
git push origin v0.9.0
```

开发测试时，可以设置环境变量 `NETPULSE_PROFILE=dev`，或者加参数 `--profile=dev`。测试版会使用独立的数据文件夹（`%LOCALAPPDATA%\NetPulse-dev`）、独立的单实例锁和独立的开机启动项，可以和日常使用的版本同时运行。

## 项目结构

| 路径 | 内容 |
|---|---|
| `src/NetPulse.Core` | 与界面无关的逻辑：速度采样、流量账本、计费周期、套餐提醒、进程速率、测速引擎与统计、Ping 统计、Wi-Fi 配置解析与二维码内容、设置存储（原子写入，文件损坏时自动回退） |
| `src/NetPulse/Platform` | Windows 接口：ETW 内核网络跟踪、Native Wifi、ARP 表、Windows 防火墙规则、按用户安装、管理员提权重启、以管理员身份开机启动（计划任务） |
| `src/NetPulse` | WinForms 界面：悬浮窗、托盘、主窗口（流量统计、实时速度、进程流量、Wi-Fi、测速、网络工具、设置） |
| `build/publish.ps1` | 发布脚本：两种 exe、可选签名、SHA-256 校验值 |
| `.github/workflows` | GitHub Actions：CI 和按标签发布 |
| `tests/NetPulse.Core.Tests` | xUnit 单元测试，包括一个用本地假服务器离线跑通完整测速流程的测试 |

第三方依赖只有 [QRCoder](https://github.com/codebude/QRCoder)（MIT 许可），只用它生成二维码矩阵，绘制由本项目完成。
